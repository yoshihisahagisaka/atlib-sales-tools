# 無料IT経営診断V1｜入力・分析・レポーティング 再設計Decision

決定日：2026-09-25  /  状態：Business・UX方針確定、実装未着手

## 1. 確定する業務フロー

顧客Webアンケート（任意） → 専用ヒアリング記録画面 → 共通分析画面 → Human Review → 経営フィードバックレポート／PDF。

- 入口A：事前Web回答あり。元回答を設問ごとに参照し、ヒアリング時の発言・追加回答を別記録する。
- 入口B：事前Web回答なし。ヒアリングで初回回答を取得する。
- どちらも同じ分析工程に進める。Web回答の存在を分析の必須条件にしない。
- 顧客先では記録、帰社後は分析、承認後はレポーティング。案件の識別子・設問IDは工程を通して共通とする。

## 2. 画面責務

- 顧客Webアンケート：顧客本人が入力する既存画面。既存設問・選択肢を共通マスターとして再利用。
- 専用ヒアリング記録：既存アンケートに似た営業向け画面。事前回答の有無に応じて表示を切り替える。回答、発言、未確認を途中保存。AI分析や改善提案を主機能にしない。旧代理入力の資産を再利用元とする。
- 分析ワークスペース：回答原本とヒアリング記録を自動連携し、Fact、Unknown、矛盾・差異、担当者補足、課題仮説、改善候補を区別して整理する。アンケートの二重入力を要求しない。
- レポート：Human Reviewで承認された版から社内用・顧客用の開示内容を区別して出力。既存のレポート版管理・印刷／PDF保存の再利用可能性を検証する。

## 3. Fact・原本・訂正の原則

- 顧客Web回答、ヒアリング時の回答・発言、帰社後の担当者補足、AI推論、担当者判断を出典と種別付きで分離する。
- 元回答を黙って上書きしない。事前回答とヒアリング回答が異なれば双方を保持し、差異として分析画面に提示する。どちらかを自動的に正としない。
- 補足と訂正は別操作。訂正時は変更前後、変更者、日時、理由、出典を記録し、元の値を追跡可能にする。
- AI提案は人間の承認を代替しない。診断前の確認計画と診断後の分析・開示内容の承認対象を混同しない。

## 4. 実装上の制約と順序

1. 既存Git履歴、docs、Canonical、現在の状態遷移・保存API・設問定義・レポート実装を確認し、Fit/Gapを記録する。
2. 現行レビュー版をバックアップし、隔離環境でヒアリング記録のデータモデルと保存・履歴を先に整える。画面だけを再編集可能にしない。
3. 既存代理入力の設問・UI部品を再利用し、Web回答あり／なしの両パターンを実装する。
4. 共通分析画面へ出典付きで連携し、補足・仮説・判断を分離する。
5. Human Reviewとレポート版管理・PDF出力に接続し、両入口、差異、訂正、監査のシナリオをテストする。

対象は `C:\atlib\atlib-diagnosis-v1-test` の隔離レビュー環境のみ。元の `C:\atlib\atlib-sales-launch`、本番環境、実顧客データは変更しない。現行MAIN／CONTEXTレビュー版は比較用に保持する。
