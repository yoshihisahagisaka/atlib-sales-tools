Owner decision superseding the preceding independent-page direction: SECU:MIE is one business unit, with WEB and Insight as two diagnosis functions. Existing Sales Tools foundation remains unchanged; one staff entry /admin/secumie-general-leads.html. No common foundation, portal, CRM or KPI changes. Keep diagnosis results service-specific, contact consent and sales progress independent of diagnosis and consultation. Staff detail shows contact/consent, diagnostic facts, consultation note/time, staff status/note. No routine personal data in shared dashboard or logs.
- Diagnosis lifecycle RECEIVED / COMPLETED / FAILED (retry allowed within authorized receipt; abandoned RECEIVED stays visible). Consultation NONE / REQUESTED; scheduling is not inferred from TimeRex redirect. Sales NEW / CONTACTED / PROPOSAL / WON / LOST / CLOSED, independent from diagnosis and consultation. Staff cannot use outreach status as automatic evidence of consent.
- One record per accepted diagnosis attempt, not one per email. Idempotency key + canonical payload hash; same key/same body returns original receipt, conflict is rejected, no duplicate on retry. Receipt is cryptographically random, hash stored only (or server-derived scoped proof); public capability authorizes only own service and attempt, never list/read/contact modification. DB insert before starting diagnosis, storage failure stops start with retryable error. Completion delivery must not put result behind consultation or paid gate; if completion write fails after diagnosis, result remains visible and safe retry of persistence is offered, no silent success. WEB persists structured factual result, not executable HTML; Insight server validates eight approved answer IDs and computes priorities using current engine, stores IDs/version/summary. Any data stored must be disclosed. No report HTML or PII in logs/localStorage.
- Consultation records against original lead, uses existing notification/TimeRex. Persist intent before notification, distinguish notification delivery failure from requested; same receipt retry must not create duplicate lead. Do not infer appointment booked. Staff status update + actor/time audit, no arbitrary SQL, no deletion in staff UI. Test/synthetic designation kept out of KPI. No export until authorization/retention policy is approved.
