```ts
import type { GapReviewResult } from './paidAssessmentGapReview';
import type { PreparationSourceRef } from './paidAssessmentPreparation';

export interface RootCauseEvidenceRef {
  source: PreparationSourceRef;
  relation: 'SUPPORTS' | 'CONTRADICTS';
  verification: 'VERIFIED_REFERENCE' | 'UNVERIFIED_STATEMENT' | 'UNKNOWN';
  note: string;
}
export interface RootCauseHypothesis {
  id: string;
  gapId: string;
  statement: string; // explicitly supplied hypothesis, never generated by this function
  rationale: string;
  evidence: readonly RootCauseEvidenceRef[];
  openQuestions: readonly string[];
  proposedBy?: string; // attribution only, not authority
}
export type RootCauseReviewState =
  | 'HYPOTHESIS_WITH_VERIFIED_SUPPORT'
  | 'HYPOTHESIS_CONTESTED'
  | 'HYPOTHESIS_UNSUBSTANTIATED'
  | 'BLOCKED_BY_GAP_EVIDENCE';
export interface RootCauseReviewResult {
  hypotheses: Array<RootCauseHypothesis & { state: RootCauseReviewState }>;
  counts: Record<RootCauseReviewState, number>;
}
export function reviewPaidAssessmentRootCauses(
  gaps: GapReviewResult,
  hypotheses: readonly RootCauseHypothesis[],
): RootCauseReviewResult;
```

## Algorithm / epistemic safety
1. Validate `gaps.items` array and unique nonblank gap IDs, exact C1 state enum. Treat C1 as a review projection only, not an authorization token. Validate hypothesis ID unique/nonblank, gapId points to an existing gap, statement and rationale nonblank, optional proposedBy nonblank. Validate evidence array, openQuestions array; no implicit question creation.
2. Evidence source must have valid source kind, nonblank ID, positive integer version and optional 64-character lowercase hex hash. Validate note nonblank and relation enum. `VERIFIED_REFERENCE` requires source kind `CORE_VERIFIED_REFERENCE`; other states must never count as verified support/contradiction. Do not independently query FACTACT or infer verification.
3. If linked gap state is not `CONFIRMED_DIFFERENCE`, state `BLOCKED_BY_GAP_EVIDENCE`, regardless of evidence list or hypothesis wording.
4. Otherwise, if any **verified** contradictory evidence exists, state `HYPOTHESIS_CONTESTED` (even when verified support also exists).
5. Otherwise, if any **verified** supporting evidence exists, state `HYPOTHESIS_WITH_VERIFIED_SUPPORT`.
6. Otherwise state `HYPOTHESIS_UNSUBSTANTIATED`. UNKNOWN or unverified statements cannot establish support or contradiction.
7. These are **hypothesis review states**, never `ROOT_CAUSE_CONFIRMED`. Verified supporting evidence does not logically prove causality; a later human review/decision and authorized record are separate. Do not create a score, severity, priority, ACT, maturity assessment, investment or automatic finding.
8. Preserve hypothesis/evidence/question input order, all source refs, copy nested objects/arrays without mutating input. Empty hypotheses is valid (all zero counts); empty gaps with hypotheses is rejected due to unknown gap ID.
9. Do not require an evidence item for every hypothesis: absence is `HYPOTHESIS_UNSUBSTANTIATED` when gap confirmed. No forced work from UNKNOWN.

## Tests
- Confirmed C1 gap + verified support → `HYPOTHESIS_WITH_VERIFIED_SUPPORT`, never confirmed cause.
- Confirmed gap + verified contradict → `HYPOTHESIS_CONTESTED`; mixed support and contradiction also contested.
- Unverified supporting statement or UNKNOWN → `HYPOTHESIS_UNSUBSTANTIATED`.
- C1 insufficient/no-difference gap blocks all cause statuses.
- Empty evidence, empty questions and zero hypotheses valid.
- Invalid source kind, verification-state mismatch, hash/version, blank notes/questions, duplicate IDs, unknown gap ID, invalid relation/state fail closed.
- Stable order, provenance, immutability, deep-detached output, deterministic repeated calls.
